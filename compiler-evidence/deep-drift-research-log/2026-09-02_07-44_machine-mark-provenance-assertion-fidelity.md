# Deep Drift Research Update - MMPAF

## Machine-Mark / Provenance-Assertion Fidelity

**Research date:** 2 September 2026  
**Primary fresh delta:** Anthropic machine-readable marking and signed provenance metadata for Claude-generated content  
**Scope:** AI-generated text marking, file provenance, C2PA, copy-paste persistence, format conversion loss, authorship ambiguity, creator workflow provenance.

## Executive finding

Anthropic now documents a cross-product content-marking architecture for supported Claude models. Models launched in the EU on or after 2 August 2026 support machine-readable marking at launch. Generated text carries an embedded watermark, while supported generated files carry digitally signed provenance metadata. Anthropic says the marking applies across Claude Platform (API), Claude, Claude Code, Claude Cowork, and Claude Tag, wherever Claude is offered, subject to feature and file-type support.

The important Deep Drift finding is not simply that AI content can be marked. It is that the platform itself explicitly limits what the mark means.

```text
MARK DETECTED
!= CLAUDE AUTHORED THE UNDERLYING IDEAS

MARK DETECTED
!= COMPLETE PROVENANCE

NO MARK DETECTED
!= NO CLAUDE PROCESSING

FILE METADATA PRESENT
!= METADATA WILL SURVIVE CONVERSION

TEXT WATERMARK PRESENT
!= WATERMARK WILL SURVIVE HEAVY EDITING
```

Machine-readable provenance is therefore an **assertion layer**, not a complete reconstruction layer.

## New node

### Machine-Mark / Provenance-Assertion Fidelity (MMPAF)

Anthropic's current marking model has two channels:

```text
CLAUDE OUTPUT
    |
    +--> TEXT
    |     |
    |     +--> embedded machine-readable watermark
    |
    +--> SUPPORTED FILE
          |
          +--> signed provenance metadata
                |
                +--> C2PA Content Credential
```

These channels behave differently under downstream transformation.

## 1. Text watermark can survive copy-paste

Anthropic states that the watermark is embedded in generated text itself. Because it travels with the text, it can persist when users copy and paste text elsewhere and may survive some editing.

That gives Deep Drift a new copy-paste distinction:

```text
COPY-PASTE
!= PROVENANCE LOSS BY DEFAULT
```

Historically, copy-paste often destroyed visible lineage. A model-level watermark attempts to make some lineage survive the manual transfer.

But that survival is probabilistic, not absolute.

```text
COPY
-> PASTE
-> LIGHT EDIT
= MARK MAY SURVIVE

COPY
-> PASTE
-> HEAVY EDIT / PARAPHRASE / TRANSLATE / MIX
= MARK MAY DISAPPEAR
```

The transfer channel is therefore no longer simply "lossy" or "preserving." It has degrees of provenance persistence.

## 2. File provenance becomes cryptographically signed, but only where supported

For supported files such as SVG, PNG, and JPG, Anthropic attaches signed provenance metadata using the Coalition for Content Provenance and Authenticity (C2PA) standard.

A valid Content Credential can indicate that a file was processed by Claude and can support tamper detection.

This is stronger than ordinary metadata because the provenance claim is signed.

But:

```text
SIGNED PROCESSING CLAIM
!= AUTHORSHIP CLAIM
```

Claude may have proofread, translated, summarized, converted, or otherwise processed material whose underlying ideas, data, or authorship originated elsewhere.

For creator research, that distinction is critical.

## 3. "Processed by Claude" is a different claim from "generated by Claude"

Anthropic explicitly warns that a detected mark does not prove full provenance.

A marked output can contain:

```text
human-authored source
+ Claude translation
+ human revision
```

or:

```text
third-party data
+ Claude formatting
+ Claude file conversion
```

Yet the resulting content may still carry a Claude mark.

Deep Drift therefore needs a vocabulary separation:

```text
MODEL PROCESSING
MODEL GENERATION
MODEL TRANSFORMATION
HUMAN AUTHORSHIP
SOURCE AUTHORSHIP
FINAL EDITORSHIP
```

These cannot be compressed into a binary AI / non-AI label.

## 4. Absence of a mark is weak negative evidence

Anthropic documents several reasons a Claude-processed output may no longer carry a detectable mark:

- the model predates marking support;
- text was heavily edited, paraphrased, translated, or mixed with other writing;
- the text passage is too short;
- file metadata was stripped by conversion, re-saving, screenshots, or other processing;
- the execution platform, feature, or file type did not support the relevant marking method.

Therefore:

```text
NO MARK
!= NO AI
```

This is one of the strongest provenance cautions in the current platform landscape.

A detector can establish some positive evidence, but lack of detection cannot safely establish human-only origin.

## 5. Format conversion becomes a provenance-destruction event

This is directly relevant to the Deep Drift DOCX/PDF/export watch.

Anthropic explicitly lists format conversion and re-saving as mechanisms that can strip file provenance metadata.

The creator chain can therefore be:

```text
CLAUDE GENERATED FILE
      |
      +--> signed provenance metadata
      |
      v
CONVERT / RE-SAVE / SCREENSHOT
      |
      X metadata stripped
      |
      v
PDF / DOCX / IMAGE DERIVATIVE
```

A downstream artifact may be genuinely derived from Claude while carrying none of the original machine-readable file provenance.

This means export should preserve both:

```text
ORIGINAL MARKED OBJECT
AND
DERIVATIVE OBJECT
```

plus the transformation event between them.

## 6. Cross-surface marking makes model provenance broader than application provenance

Anthropic says marking is applied at the model level across Claude products, including API, Claude, Code, Cowork, and Tag. Supported models accessed through AWS, Google Cloud, or Microsoft Foundry also carry text watermarks. Signed file provenance depends on whether the hosting platform supports Claude file generation.

So:

```text
MODEL-LEVEL MARK
CAN CROSS PRODUCT SURFACES

FILE PROVENANCE SUPPORT
CAN STILL VARY BY HOST PLATFORM
```

This creates another separation:

```text
MODEL PROVENANCE COVERAGE
!= FILE-PROVENANCE FEATURE COVERAGE
```

A research archive must preserve both model identity and execution surface.

## 7. Detection infrastructure itself becomes a provenance dependency

Anthropic provides a free Content Checker for Claude-issued file credentials and says text-watermark detection is currently in private preview for eligible groups such as regulators, media, fact-checkers, independent researchers, educational organizations, civil society groups, and certain enterprises.

Thus:

```text
MARK EXISTS
!= EVERYONE CAN DETECT IT

DETECTION ACCESS
!= MARK CREATION ACCESS
```

The evidentiary usefulness of a mark depends partly on detector availability and future documentation.

Deep Drift should therefore preserve not only the mark but also:

```text
detector identity
detector version
verification timestamp
verification result
verification access class
```

## New failure classes

### Mark-Equals-Authorship Fallacy
Treating a detected Claude mark as proof that Claude originated the underlying ideas, data, or authorship.

### No-Mark-Equals-Human Fallacy
Treating absence of a detectable mark as proof of non-AI origin.

### Processing-Generation Collapse
Failing to distinguish model processing, transformation, proofreading, translation, and original generation.

### Conversion-Provenance Erasure
Producing a derivative file through conversion or re-saving without preserving the marked source object.

### Detector-Availability Blindness
Assuming every provenance mark can be independently verified by every researcher.

### Surface-Provenance Collapse
Treating model-level marking and host-platform file provenance support as equivalent.

### Positive-Signal Overclaim
Using a machine-readable mark as if it established complete causal lineage.

### Negative-Signal Overclaim
Using failed detection as if it excluded prior AI processing.

## Deep Drift benchmark additions

**Machine-Mark Presence Fidelity (MMPF)**  
Can the archive record whether a supported text or file mark was present at each workflow stage?

**Processing-vs-Authorship Fidelity (PAF)**  
Can Claude processing be distinguished from source authorship and final authorship?

**C2PA Credential Fidelity (CCF)**  
Can signed Content Credentials be preserved, validated, and linked to their source artifact?

**Mark-Survival Fidelity (MSF)**  
Can copy-paste, editing, translation, conversion, re-saving, and screenshot events be tracked against mark persistence?

**Positive-Evidence Boundary Fidelity (PEBF)**  
Can a detected mark be represented as evidence of processing without overclaiming full provenance?

**Negative-Evidence Boundary Fidelity (NEBF)**  
Can failed detection be prevented from becoming a false human-authorship conclusion?

**Detector-State Fidelity (DSF)**  
Can detector identity, access class, version, verification time, and result be reconstructed?

**Marked-Source-to-Derivative Fidelity (MSDF)**  
Can downstream DOCX, PDF, images, screenshots, and exports be traced back to the original marked source even when provenance metadata no longer survives?

## Canonical Deep Drift requirement

> Every material AI-assisted creator workflow that produces or encounters machine-readable provenance marks should preserve a machine-readable marking manifest that records the model and model-support status; execution product and host platform; artifact type; text-watermark presence where detectable; signed file-provenance credential and C2PA payload where available; credential signature state; detector identity, version, access class, timestamp, and result; source authorship claims; model processing role; human editing role; every copy-paste, translation, paraphrase, merge, conversion, re-save, screenshot, and export event; mark-survival state after each transformation; and every downstream DOCX, PDF, image, message, publication, or research artifact. A detected AI mark must never be treated as complete authorship proof, and absence of a detected mark must never be treated as proof that no AI system processed the content.

## Broader creator-workflow trend

The provenance landscape is moving from:

```text
AI USE
= DISCLOSURE BY HUMAN
```

toward:

```text
AI USE
=
HUMAN DISCLOSURE
+
MODEL-LEVEL WATERMARK
+
SIGNED FILE PROVENANCE
+
DETECTOR
+
TRANSFORMATION HISTORY
```

This is progress, but not closure.

Machine-readable provenance does not replace research provenance. It becomes one evidentiary layer inside it.

The Deep Drift principle is:

**A mark is a claim about processing history, not a substitute for processing history.**
