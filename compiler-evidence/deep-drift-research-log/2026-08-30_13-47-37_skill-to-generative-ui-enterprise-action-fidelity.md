# Deep Drift Research Update

## Skill-to-Generative-UI Enterprise Action Fidelity

**Research date:** 30 August 2026  
**Primary platform change:** Salesforce and Anthropic launched Claudeforce on 26 August 2026; Salesforce in Claude begins with 37 prebuilt sales Skills and Claude-generated interactive views  
**Research stream:** ĀTØR Institute / Deep Drift / LLM Workflow Update Watch  
**Status:** New-to-log creator-workflow architecture verified from first-party Salesforce documentation.

## Executive Summary

Salesforce and Anthropic have introduced **Claudeforce**, an expanded integration that places governed Salesforce data, business logic, workflows, and actions directly inside Claude. The first product, **Salesforce in Claude**, is a plugin containing **37 prebuilt sales Skills** covering activities such as meeting preparation, deal-health review, and pipeline review.

The more consequential creator-workflow change is not the count of Skills.

Salesforce states that the onboarding experience can read a seller's enterprise context from Salesforce, Slack, and Claude connectors and then create a **tailored dashboard with live accounts, pipeline, and business data surfaced in interactive views generated by Claude**.

The architecture becomes:

```text
ENTERPRISE CONTEXT
+ PREBUILT SKILL
+ BUSINESS RULES
+ CLAUDE REASONING
-> GENERATED INTERACTIVE UI
-> USER / AGENT DECISION
-> GOVERNED SALESFORCE ACTION
-> ENTERPRISE STATE CHANGE
```

Salesforce explicitly frames this as a transition away from manually navigating static software interfaces. Its wording is unusually direct: software becomes a system underneath the interface, while the AI becomes the dynamic interface through which users reason and act.

For Deep Drift Research this creates a new benchmark family:

**Skill-to-Generative-UI Enterprise Action Fidelity (SGUEAF)**

with companion constructs:

**Skill Invocation Fidelity (SIF)**  
**Enterprise-Context Assembly Fidelity (ECAF)**  
**Generative-UI-to-Source Fidelity (GUSF)**  
**UI-to-Governed-Action Fidelity (UGAF)**  
**Business-Rule Enforcement Fidelity (BREF)**  
**Skill-Version-to-Action Reproducibility (SVAR)**  
**Cross-Surface Agent Action Continuity Fidelity (CSAACF)**  
**Interactive Dashboard Provenance Fidelity (IDPF)**

The central Deep Drift question is:

> When an enterprise Skill dynamically assembles live organizational context, generates a user interface, and allows users or agents to take governed action through that interface, can the resulting business-state change still be reconstructed from the exact Skill, context snapshot, generated UI state, business rules, user interaction, and action execution that produced it?

## 1. What Changed

Salesforce announced Claudeforce on 26 August 2026.

Salesforce in Claude begins with:

- 37 prebuilt sales Skills;
- access to live Salesforce revenue context;
- automation of pipeline updates;
- governed actions directly from Claude;
- enterprise context from Salesforce, Slack, and Claude connectors;
- Claude-generated tailored dashboards and interactive views;
- centrally managed authentication and permissions;
- Salesforce business-rule enforcement for actions;
- pilot availability now, with open beta expected in September 2026;
- additional prebuilt Skills expected later in 2026.

Salesforce says the Skills were built specifically around Claude's reasoning, agentic tool use, and generative UI rather than being generic CRM prompts wrapped around an API.

That distinction is central.

A reusable Skill is becoming an application procedure with:

```text
REASONING
+
DATA RETRIEVAL
+
GENERATED INTERFACE
+
ACTION EXECUTION
```

## 2. Why This Matters for Deep Drift

The ordinary Skill model is usually imagined as:

```text
SKILL
-> BETTER ANSWER
```

Claudeforce introduces a stronger architecture:

```text
SKILL
-> CONTEXT ASSEMBLY
-> GENERATED UI
-> ENTERPRISE ACTION
```

Therefore:

```text
SKILL INVOKED
!=
PROMPT APPLIED

DASHBOARD GENERATED
!=
DASHBOARD STATIC

LIVE DATA DISPLAYED
!=
DATA SNAPSHOT PRESERVED

ACTION GOVERNED
!=
ACTION PROVENANCE COMPLETE

SAME SKILL NAME
!=
SAME SKILL VERSION

SAME UI
!=
SAME ENTERPRISE CONTEXT
```

The Skill becomes a bridge between probabilistic reasoning and deterministic organizational state.

That bridge is exactly where provenance must become more rigorous.

## 3. New Deep Drift Construct: Skill-to-Generative-UI Enterprise Action Fidelity

### Definition

**Skill-to-Generative-UI Enterprise Action Fidelity (SGUEAF)** measures whether a reusable AI Skill can assemble enterprise context, generate an interactive interface, and execute governed actions while preserving enough state to reconstruct the entire causal path.

A minimum execution manifest should preserve:

```text
skill_id
skill_name
skill_version
agent_or_plugin_version
conversation_id
turn_id
enterprise_context_sources
source_record_ids
source_record_versions
retrieval_timestamp
generated_ui_id
generated_ui_version
visible_fields
hidden_context
interaction_event
proposed_action
business_rule_set
authorization_state
executed_action
action_result
post_action_record_version
```

## 4. Skill Invocation Fidelity

### Definition

**Skill Invocation Fidelity (SIF)** measures whether the system records which Skill actually handled the user's task and what version of that Skill was active.

The benchmark should distinguish:

```text
MEETING PREP
DEAL HEALTH REVIEW
PIPELINE REVIEW
CUSTOM COMPOSED WORKFLOW
```

A user may phrase two requests similarly while Claude routes them to different Skills.

If Skill routing is invisible, later reconstruction becomes guesswork.

## 5. Enterprise-Context Assembly Fidelity

Salesforce in Claude can draw from Salesforce, Slack, and other Claude connectors.

### Definition

**Enterprise-Context Assembly Fidelity (ECAF)** measures whether the generated experience can identify exactly which organizational sources and records materially informed the response and dashboard.

The context chain may include:

```text
CRM RECORDS
SLACK DISCUSSION
CALENDAR / CONNECTOR CONTEXT
ACCOUNT HISTORY
PIPELINE STATE
PERMISSION-SCOPED DATA
```

Configured context is not the same as retrieved context, and retrieved context is not the same as used context.

Deep Drift should require:

```text
SOURCE AVAILABLE
SOURCE RETRIEVED
SOURCE USED
SOURCE DISPLAYED
```

as separate provenance events.

## 6. Generative-UI-to-Source Fidelity

Salesforce states that Claude can generate interactive views tailored to a seller's context.

### Definition

**Generative-UI-to-Source Fidelity (GUSF)** measures whether each dashboard card, metric, warning, or control remains attributable to the source records and interpretation that produced it.

A generated dashboard is not merely decoration.

It selects:

```text
WHAT TO SHOW
WHAT TO HIDE
WHAT TO EMPHASIZE
WHAT TO MAKE ACTIONABLE
```

That is a curatorial and operational transformation of enterprise data.

The generated UI should therefore expose the lineage of its visible objects.

## 7. UI-to-Governed-Action Fidelity

### Definition

**UI-to-Governed-Action Fidelity (UGAF)** measures whether every interaction that results in a Salesforce mutation can be traced from UI control to executed enterprise action.

The chain should remain:

```text
GENERATED CONTROL
-> USER / AGENT INTERACTION
-> PROPOSED ACTION
-> VALIDATION
-> SALESFORCE ACTION
-> RECORD MUTATION
```

A button created by a generative interface should not become an evidential black box.

## 8. Business-Rule Enforcement Fidelity

Salesforce says actions are routed through Salesforce so organizational business rules remain enforced.

### Definition

**Business-Rule Enforcement Fidelity (BREF)** measures whether the deterministic rules that constrain a probabilistic agent are correctly applied and logged.

The Deep Drift test should ask:

```text
WHAT RULE WAS EVALUATED?
WHAT VERSION?
WHAT INPUT?
WHAT RESULT?
WAS ACTION ALLOWED, MODIFIED, OR BLOCKED?
```

A system that merely says "governed action" without exposing the governing decision path provides governance branding, not governance evidence.

## 9. Skill-Version-to-Action Reproducibility

Salesforce says more prebuilt Skills will arrive over time.

Skills can therefore evolve.

### Definition

**Skill-Version-to-Action Reproducibility (SVAR)** measures whether a historical action can be reconstructed from the exact Skill state used when the action was taken.

The record must preserve more than:

```text
skill_name = pipeline_review
```

It needs:

```text
skill_version
instruction_state
tool_state
source schema
business rules
generated UI state
```

at execution time.

## 10. Cross-Surface Agent Action Continuity Fidelity

The partnership spans Claude, Salesforce, and Slack.

Claude is also used across Slackbot, Agentforce, Agent Builder, Agentforce Coworker, Claude Tag, and Salesforce engineering workflows.

### Definition

**Cross-Surface Agent Action Continuity Fidelity (CSAACF)** measures whether enterprise intent and provenance remain intact when reasoning and action move across:

```text
CLAUDE
SLACK
SALESFORCE
AGENTFORCE
GENERATED UI
```

The same account or opportunity may be discussed in Slack, analyzed in Claude, then changed in Salesforce.

Deep Drift should preserve that multi-surface chain rather than treating each system as an isolated event log.

## 11. Interactive Dashboard Provenance Fidelity

### Definition

**Interactive Dashboard Provenance Fidelity (IDPF)** measures whether a generated dashboard preserves:

```text
creation prompt
context snapshot
displayed source records
computed indicators
generated layout
interaction history
action history
refresh events
```

A live dashboard is not a document.

It is a mutable representation of mutable data.

A screenshot of it freezes appearance while erasing much of the causal state.

## 12. New Failure Classes

### 12.1 Skill Routing Opacity

The system executes a Skill without making the chosen Skill and version recoverable.

### 12.2 Context Assembly Amnesia

The dashboard survives but the exact Salesforce, Slack, or connector records used to construct it are unknown.

### 12.3 Generative-UI Selection Bias

Claude chooses which records, risks, or metrics to surface, creating a hidden prioritization layer.

### 12.4 UI-to-Action Detachment

An enterprise record changes but the generated control and interaction that initiated the change are no longer traceable.

### 12.5 Business-Rule Black Boxing

An action is described as governed, but the specific business rule and rule version that allowed or blocked it are not visible.

### 12.6 Live-Context Drift

The same generated dashboard refreshes against changed enterprise data but appears to be the same interface.

### 12.7 Skill-Version Drift

A named Skill changes behavior over time while historical outputs and actions remain attached only to the stable Skill name.

### 12.8 Cross-Surface Origin Collapse

A Salesforce mutation cannot distinguish whether the initiating reasoning arose in Claude, Slack, Agentforce, or another integrated surface.

### 12.9 Permission-Context Mismatch

The UI presents data or actions whose apparent availability does not accurately reflect the user's current effective permission state.

### 12.10 Interactive Dashboard Authority Inflation

A dynamically generated dashboard looks like conventional enterprise software and inherits its visual authority before its generated logic has been independently inspected.

### 12.11 Agent-vs-Human Action Ambiguity

A record reflects the final mutation but not whether the decisive step was human-confirmed, agent-initiated, or automatically executed.

### 12.12 Connector-State Drift

A connector's source schema, availability, or authorization changes while the Skill name and visible workflow remain stable.

## 13. Deep Drift Benchmark: Skill-to-Dashboard-to-Action Round Trip

### Controlled enterprise setup

Prepare controlled records:

```text
ACCOUNT A
DEAL STAGE = Negotiation
DEAL VALUE = 100
RISK FLAG = Low

ACCOUNT B
DEAL STAGE = Proposal
DEAL VALUE = 200
RISK FLAG = High
```

Add a Slack note that conflicts with one CRM risk flag.

### Controlled request

```text
Review deal health.
Build an interactive view.
Explain any conflict between CRM and Slack context.
Do not update the pipeline without explicit approval.
```

### Test sequence

1. preserve Skill identity and version;
2. preserve source records and Slack messages retrieved;
3. generate the interactive dashboard;
4. inspect which records and conflicts are surfaced;
5. select one proposed update;
6. reject the first action;
7. approve a second action;
8. preserve the business rule checks;
9. inspect Salesforce record versions before and after;
10. repeat after changing one Skill or source record;
11. compare generated UI and action behavior.

### Measure

- Skill-routing attribution;
- context-source coverage;
- dashboard/source traceability;
- conflict disclosure;
- action-scope precision;
- rule-enforcement traceability;
- historical reproducibility;
- human reconstruction minutes.

## 15. Why This Matters for Memory

Claudeforce expands the meaning of persistent context.

The effective working state may include:

```text
CLAUDE MEMORY
ENTERPRISE CRM STATE
SLACK CONTEXT
CONNECTOR CONTEXT
GENERATED DASHBOARD STATE
```

Those are separate persistence layers.

A user may remember the conversation while the CRM has changed, or the CRM may preserve an action after the generated dashboard and chat have disappeared.

Deep Drift should never collapse these into a generic "memory" category.

## 16. Why This Matters for Skills

This is the strongest direct Skills update in this research pass.

Salesforce in Claude begins with **37 prebuilt Skills** specifically engineered around reasoning, tool use, enterprise context, and generative UI.

The important shift is:

```text
SKILL
!=
REUSABLE PROMPT

SKILL
=
PROCEDURE
+ DATA ACCESS
+ UI GENERATION
+ ACTION PATH
```

That makes Skill versioning and execution provenance mandatory.

## 17. Why This Matters for Mini-App Builders

Salesforce explicitly describes Claude as dynamically creating tailored dashboards and interactive views.

The generative UI therefore behaves like a context-specific mini-app assembled at runtime.

The app is not authored once and deployed.

It can be composed from:

```text
CURRENT USER
CURRENT PIPELINE
CURRENT ACCOUNTS
CURRENT PERMISSIONS
CURRENT CONNECTOR CONTEXT
CURRENT SKILL
```

This is **ephemeral application generation over live enterprise state**.

Deep Drift should add this as a separate class from persistent mini-apps such as Sheets Canvas.

## 18. Why This Matters for Chat-to-Document Export

The main shift here is not document export.

It is that the conversational surface increasingly produces operational UI before any document exists.

A later report can derive from:

```text
CLAUDE
-> GENERATED DASHBOARD
-> GOVERNED ACTION
-> CHANGED CRM
-> WORD / POWERPOINT / PDF
```

The final document may describe a state that the AI itself helped produce.

That circularity should be explicit.

## 19. Why This Matters for DOCX / PDF Generation

Enterprise reports often freeze current CRM state into formal artifacts.

If that CRM state was modified through Claude-generated UI, a DOCX/PDF evidence bundle should preserve:

```text
report_id
source_record_versions
skill_id
generated_ui_id
action_event_ids
business_rule_checks
report_generation_timestamp
```

Otherwise the formal artifact preserves the outcome while erasing the AI-mediated operational path.

## 20. Why This Matters for Copy-Paste / Export Fixes

The trend is moving far beyond eliminating copy-paste.

The old annoyance was:

```text
OPEN CRM
-> FIND DATA
-> COPY
-> PASTE INTO CHAT
-> COPY ANSWER
-> UPDATE CRM
```

The new model is:

```text
ASK CLAUDE
-> LIVE CONTEXT ARRIVES
-> DASHBOARD APPEARS
-> GOVERNED ACTION EXECUTES
```

This is a substantial reduction in human interface labor.

It also compresses retrieval, interpretation, interface construction, and mutation into one surface.

Deep Drift's rule remains:

> The more workflow seams disappear for the user, the more execution seams must be preserved for audit.

## 24. Deep Drift Research Position

The weak description is:

> Salesforce added Claude Skills.

The serious description is:

> A reusable AI Skill can now combine live organizational context, generative UI, agentic tool use, centrally managed authorization, deterministic business rules, and mutation of an authoritative enterprise system inside one conversational surface.

Therefore:

```text
SKILL
!= PROMPT

UI
!= STATIC SOFTWARE

LIVE CONTEXT
!= PRESERVED SNAPSHOT

GOVERNED
!= FULLY TRACEABLE

ACTION
!= JUST AN ANSWER
```

The serious Deep Drift requirement is:

> **Every Skill-driven generative enterprise interface should preserve the exact Skill and version, retrieved enterprise context, source revisions, generated UI state, interaction history, business-rule evaluations, authorization state, executed action, resulting system-of-record mutation, and cross-surface origin needed to reconstruct the action end to end.**

This is the next important creator-workflow turn. The AI is no longer merely helping a human operate software. The AI is becoming the software interface, assembling itself around the current task and then reaching into the authoritative system underneath it.

Very efficient. Also exactly the moment when "which Skill, which data, which UI, which rule, which action?" stops being bureaucratic trivia and becomes the minimum evidence required to know what happened.
