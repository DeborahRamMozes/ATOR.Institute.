# Deep Drift Research Update - ACSLF

## Artifact Continuity & Source-Link Fidelity

**Research date:** 5 September 2026

## Executive finding

The strongest current creator-workflow trend is the move from chat output to **persistent, source-linked, editable artifacts**.

Three platform directions now reinforce each other:

1. Google Gemini can generate downloadable PDFs, DOCX, Google Docs, Sheets, Slides, CSV, LaTeX, RTF, TXT, and Markdown directly from chat, reducing manual copy-paste and reformatting.
2. OpenAI ChatGPT now places connected Google Drive files and folders in Library, keeps Docs/Sheets/Slides open beside the conversation, and where supported can update the source file directly.
3. OpenAI ChatGPT Work is positioned as a longer-running agent that can research across connected apps/files and create finished documents, spreadsheets, presentations, reports, and Sites.

This creates a new creator workflow primitive:

```text
CHAT / RESEARCH
      |
      v
CONNECTED SOURCE
      |
      v
EDITABLE ARTIFACT
      |
      +--> DOCX
      +--> PDF
      +--> SHEET
      +--> SLIDE
      +--> SITE
      |
      v
RETURN LINK TO SOURCE / WORKSPACE
```

The system is no longer only producing text. It is creating a durable object with a possible link back to source files, workspace state, permissions, and later edits.

Therefore:

```text
DOWNLOADABLE FILE
!= SOURCE-LINKED ARTIFACT

EDITABLE
!= REPRODUCIBLE

SAME CONTENT
!= SAME SOURCE RELATIONSHIP

EXPORT SUCCESS
!= ROUND-TRIP FIDELITY

VISIBLE FILE
!= COMPLETE WORKFLOW HISTORY
```

The new provenance object is the **artifact continuity chain**.

## 1. Chat-to-file is becoming native

Google Gemini's April 29, 2026 update allows users to generate downloadable and ready-to-share files directly in chat, including PDF, DOCX, Google Docs, Sheets, Slides, XLSX, CSV, LaTeX, TXT, RTF, and Markdown.

Google explicitly frames the feature as removing the need to copy, paste, and reformat content into another application.

This is a real shift in workflow topology:

```text
OLD:
CHAT
-> COPY
-> PASTE
-> REFORMAT
-> SAVE

NEW:
CHAT
-> GENERATE FILE
-> DOWNLOAD / EXPORT TO DRIVE
```

## 2. Direct generation reduces friction but creates a new verification boundary

The new workflow removes manual formatting steps.

That is useful.

But it also means the first artifact is generated by a platform-specific converter whose rules may differ from the chat renderer.

Therefore:

```text
CHAT APPEARANCE
!= EXPORTED DOCX APPEARANCE

CHAT APPEARANCE
!= EXPORTED PDF APPEARANCE
```

Deep Drift should render and inspect the file, not trust the preview.

## 3. OpenAI now keeps connected source files in the workflow

OpenAI's August 13, 2026 release notes say Google Drive files and folders can be browsed from Library and added to chats without re-uploading. Docs, Sheets, and Slides can remain open beside the conversation while ChatGPT summarizes, compares, analyzes, or creates something new. Where supported and authorized, ChatGPT can update the source file directly.

This introduces a source-linked artifact chain:

```text
DRIVE SOURCE
-> CHAT ANALYSIS
-> DERIVATIVE ARTIFACT
-> POSSIBLE SOURCE UPDATE
```

The artifact is no longer necessarily a detached download.

## 4. Source-link state is a first-class variable

A generated document may be:

```text
detached
linked
linked-and-editable
linked-but-read-only
linked-with-lag
```

These are different creator workflows.

A file downloaded to a laptop may contain the same prose as a Drive-linked document while having completely different revision behavior.

## 5. ChatGPT Work adds a long-running agent layer

OpenAI describes ChatGPT Work as an agent for longer, more involved tasks that can research and analyze information, work across connected apps and files, create finished documents and other artifacts, and run scheduled tasks.

This means creator workflows can now span:

```text
plan
research
retrieve
draft
edit
export
share
monitor
```

The final file is only one point in a longer execution chain.

## 6. Scheduled work creates artifact recurrence

When an agent can run on a schedule or monitor for change, one report may have many descendants:

```text
REPORT_2026_09_05
REPORT_2026_09_06
REPORT_2026_09_07
```

If the source files, permissions, or model change between runs, the report family can drift even when the task name stays the same.

Deep Drift should preserve recurring-run lineage, not just filename similarity.

## 7. Source permissions remain part of artifact provenance

A source-linked workflow can produce different outputs for different users because the source access layer differs.

```text
SAME PROMPT
+
SAME ARTIFACT TYPE
+
DIFFERENT SOURCE PERMISSIONS
=
DIFFERENT RESULT
```

This extends prior permission and policy nodes into the artifact continuity chain.

## 8. Export and return-link behavior are separate

A platform can generate a downloadable DOCX or PDF but fail to preserve the relationship to the source workspace.

Therefore record:

```text
artifact generated
artifact downloaded
artifact linked back
artifact editable in source
artifact revision returned to source
```

A "download" button does not prove round-trip continuity.

## 9. The practical industry response is better conversion testing

The public llm2doc changelog is unusually explicit about document export failures and fixes:

- code-output mistaken for a document;
- large-document memory/time ceilings;
- oversized upload rejection;
- instant export-button feedback;
- terminal-style tables converted into real tables;
- large two-column tables surviving Word export;
- cleaner PDF page breaks;
- page cuts no longer slicing text;
- Word/PowerPoint callout preservation;
- Google Docs export clipboard fixes;
- blank extra print pages;
- PowerPoint corruption fixes.

These are not just UX details.

They expose the actual fault lines of chat-to-artifact systems:

```text
semantic content
layout
table structure
page breaks
clipboard state
file validity
export timing
```

## 10. Copy-paste is still a fallback failure boundary

Even when direct file generation exists, users still copy content between systems.

The current conversion fixes show why:

```text
COPY
-> parser
-> renderer
-> DOCX/PDF
```

can break tables, links, equations, page breaks, and clipboard state.

Deep Drift should compare:

```text
direct export path
vs
copy-paste conversion path
```

not treat them as equivalent.

## 11. Markdown is becoming a portable control surface

Gemini supports Markdown export directly.

The llm2doc changelog supports Markdown upload, Markdown-to-Word/PDF/PPTX conversion, and Markdown as a feedback/reproduction artifact.

This matters because Markdown sits between:

```text
human-readable text
machine-readable structure
multi-format conversion
version control
```

It is increasingly useful as an archival and interoperability layer, but only if the conversion path is itself versioned.

## 12. Artifact continuity is stronger than file persistence

A file saved somewhere is not necessarily part of a durable workflow.

Continuity requires:

```text
source identity
artifact identity
revision relationship
permission context
export history
return path
```

Without those, an archive may contain files but no reproducible chain.

## 13. PDFs and DOCX flatten source/workspace state

The final artifact typically preserves visible output but not:

```text
source snapshot
source permissions
connected-file state
prompt and instruction context
agent execution path
scheduled-run state
editor identity
return-link capability
```

Therefore:

```text
FINAL PDF
!= COMPLETE RESEARCH RECORD

FINAL DOCX
!= COMPLETE CREATOR WORKFLOW
```

## 14. Source-linked artifacts can create hidden update loops

If ChatGPT can update a source file directly, a later run may read its own earlier output.

```text
SOURCE
-> AI DERIVATIVE
-> SOURCE UPDATE
-> NEXT AI RUN
```

That loop can amplify a formatting or reasoning error over time.

Deep Drift should detect whether a recurring workflow reads artifacts it previously wrote.

## 15. Creator workflows now look like lightweight build systems

The emerging pattern resembles a build pipeline:

```text
source files
-> retrieval
-> prompt/instruction state
-> generation
-> format conversion
-> artifact storage
-> export/share
-> downstream revision
```

So a research log should start storing:

```text
manifest
dependencies
build input
build output
conversion path
verification
```

## New failure classes

### Download-Equals-Continuity Fallacy
Assuming a downloadable file remains linked to its source workspace.

### Preview-Equals-Export Fallacy
Assuming the chat preview and the DOCX/PDF output are structurally identical.

### Source-Link-Equals-Source-Snapshot Fallacy
Assuming a live link preserves the exact source state used at generation time.

### Recurring-Task-Equals-Static-Report Fallacy
Assuming repeated scheduled outputs are interchangeable when source files, permissions, or models may have changed.

### Self-Update-Loop Blindness
Failing to detect that an AI workflow reads artifacts it previously wrote or modified back into the source system.

## Deep Drift benchmark additions

**Artifact Continuity Fidelity (ACF)**  
Can a generated artifact be traced from source objects through generation, export, storage, and later revision?

**Source-Link Fidelity (SLF)**  
Does the final artifact preserve the intended relationship to source files and workspace state?

**Round-Trip Artifact Fidelity (RTAF)**  
Can exported artifacts be edited and returned without losing structure, permissions, or source identity?

**Recurring Artifact Lineage Fidelity (RALF)**  
Can scheduled or monitored outputs be linked to each run's source snapshot, model, and instruction state?

**Copy-vs-Direct Export Fidelity (CDEF)**  
How much quality and provenance difference exists between direct file generation and copy-paste conversion?

## DRPA-1.0 protocol additions

### SOURCE SNAPSHOT RULE

> Preserve source-object identity, snapshot time, permissions, and relevant revisions for every artifact generated from connected files.

### DIRECT-EXPORT VERIFICATION RULE

> Validate the generated DOCX, PDF, spreadsheet, presentation, or site independently of the chat preview. Preview fidelity must not be treated as export fidelity.

### RETURN-LINK RULE

> Record whether an artifact is detached, source-linked, editable in source, or capable of returning revisions to the source workspace.

### RECURRING-RUN LINEAGE RULE

> For scheduled or monitored workflows, preserve each run's source snapshot, model, instruction state, permissions, artifact revision, and verification result.

### SELF-REFERENCE DETECTION RULE

> Detect and record when a workflow reads files or documents it previously generated or modified. Self-referential update loops must be treated as a separate causal condition.

## Canonical Deep Drift requirement

> Treat creator artifacts as nodes in a source-linked continuity chain, not as isolated downloads. Preserve source snapshots, permissions, generation state, export path, verification, and return-link behavior separately.

## Deep Drift principle

> **A file is not a workflow until its ancestry and return path are preserved.**

Operationally:

> **Archive the source snapshot, the export path, and the artifact's relationship to the workspace.**
