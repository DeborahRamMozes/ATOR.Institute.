# Deep Drift Research Update — HGGIF

## Headless Governance and Generative Interface Fidelity

**Research timestamp:** 1 September 2026, 17:51 WIB  
**Scope:** memory, skills, mini-app builders, chat-to-document export, DOCX/PDF generation, copy-paste/export, and creator-workflow architecture.

## Executive finding

The strongest newly surfaced creator-workflow signal is **Salesforce in Claude / Claudeforce**, announced by Salesforce and Anthropic on 27-28 August 2026 and entering open beta in September. The integration launches as a Claude plugin containing **37 prebuilt sales Skills** and can read enterprise context from Salesforce, Slack, and Claude connectors, generate tailored interactive dashboards, and route actions back through Salesforce so company business rules remain enforced.

This adds a distinct Deep Drift node. The interface is increasingly generated by the model, but the permission model, deterministic rules, live data, and action authority remain in an external enterprise system. The visible AI surface and the governing execution surface are no longer the same object.

## New node

### Headless Governance and Generative Interface Fidelity (HGGIF)

```text
CLAUDE
  -> reasoning
  -> agentic tool use
  -> generative UI

SALESFORCE / AIFORCE
  -> live enterprise data
  -> workflows
  -> business rules
  -> MCP / APIs / CLI
  -> authentication
  -> governed actions

VISIBLE INTERFACE != GOVERNING SYSTEM
```

The same interaction can therefore have at least four independently changing layers:

```text
MODEL / REASONING LAYER
SKILL / PLUGIN LAYER
GENERATIVE INTERFACE LAYER
GOVERNED ACTION LAYER
```

A user may experience one conversational surface while the actual work is assembled from multiple systems with different ownership, retention, permission, and version histories.

## Notable changes

### 1. Skills are becoming domain applications, not prompt bundles

Salesforce in Claude launches with 37 prebuilt sales Skills for tasks including meeting preparation, deal-health review, and pipeline review. Salesforce says these were jointly engineered to use Claude's reasoning, agentic tool use, and generative UI, rather than merely wrapping generic CRM prompts around an API.

**Deep Drift implication:** Skill provenance needs more than a name and instruction file. It must record the exact Skill version, its tool dependencies, the enterprise object types it can access, the action routes it can invoke, and the policy layer constraining those actions.

### 2. Generative UI becomes a runtime artifact

The onboarding flow can read a seller's enterprise context from Salesforce, Slack, and other Claude connectors, then generate a tailored dashboard containing accounts, pipeline, live data, and interactive views.

That is mini-app behavior without a conventional fixed app-builder step:

```text
ENTERPRISE CONTEXT
      +
SKILLS
      +
MODEL REASONING
      -> GENERATED INTERACTIVE VIEW
```

The dashboard is not merely a static report. It is a context-dependent interface generated from live state.

**Deep Drift implication:** generated UI should be archived as an artifact class with its own lineage: source context, Skill set, model state, generation event, component schema if available, and the actions exposed through it.

### 3. Actions remain governed by an external deterministic system

Salesforce says actions are routed through Salesforce so business rules are enforced when an action is taken. Authentication and permissions are centrally managed by an administrator.

This creates a crucial separation:

```text
CLAUDE MAY PROPOSE OR INITIATE
       !=
SALESFORCE DECIDES WHETHER THE ACTION IS VALID
```

A chat transcript cannot prove that an action was executable, authorized, or completed. The decisive evidence may live in Salesforce policy, permission, and transaction logs.

### 4. AIforce makes enterprise software increasingly headless

Salesforce describes AIforce as an enterprise harness that exposes business data and workflows to agents through MCP servers, APIs, and CLI tools. The broader design claim is that software no longer needs to be navigated primarily through static UI; agents can operate directly on the underlying data, workflows, and rules.

**Deep Drift implication:** creator workflow provenance must represent the system behind the interface. A model-generated dashboard can disappear or regenerate while the underlying governed workflow persists.

### 5. Cross-surface model identity is becoming organizational infrastructure

Salesforce also states that Claude is available inside Agentforce as a reasoning model and is used across several Salesforce and Slack surfaces. This reinforces an earlier Deep Drift finding: the branded surface, reasoning provider, enterprise data layer, orchestration layer, and action-governance layer can all belong to different products or vendors.

HGGIF extends that earlier provider-attribution work specifically into **generated interfaces and governed enterprise action**.

## New Deep Drift failure classes

1. **Interface-Governance Collapse** — treating the visible generative UI as if it were also the system enforcing business rules.
2. **Skill-as-Prompt Reduction** — recording a Skill as text while omitting its connected tools, data scopes, action routes, and policy dependencies.
3. **Generated-UI Orphaning** — preserving screenshots or exports without the enterprise state that generated the interface.
4. **Action-Provenance Gap** — preserving the conversational instruction while losing evidence of whether the governed action was permitted and committed.
5. **Headless-System Erasure** — documenting only the chat surface while ignoring MCP/API/CLI systems operating underneath it.
6. **Central-Permission Amnesia** — failing to record administrator-managed authentication, role, and permission state that determined capability access.
7. **Live-Context Drift** — assuming a regenerated dashboard represents the same informational state as an earlier view.
8. **Cross-Surface Model Simplification** — attributing an enterprise action to one branded product when reasoning, orchestration, data, and governance span several systems.

## Benchmark additions

**Generative Interface Lineage Fidelity (GILF):** Can a generated interactive view be traced to the model, Skills, sources, and enterprise state that produced it?

**Governed Action Attribution Fidelity (GAAF):** Can an action be traced from model proposal through enterprise authorization, business-rule enforcement, and committed transaction?

**Skill Dependency Fidelity (SDF):** Are the Skill's tools, connectors, scopes, and policy dependencies recorded alongside its instruction content?

**Headless System Visibility Fidelity (HSVF):** Does the archive identify the MCP/API/CLI systems that performed material work behind the conversational surface?

**Permission-State Fidelity (PSF):** Can the relevant administrator, role, authentication, and permission state be reconstructed for the execution event?

**Live-Context Snapshot Fidelity (LCSF):** Is the exact business-data state feeding a generated interface recoverable or at least timestamped and identified?

**Interface-to-Transaction Fidelity (ITF):** Can a UI interaction be linked to the underlying governed transaction rather than treated as evidence by itself?

**Cross-Surface Execution Fidelity (CSEF):** Can the same model or Skill operating across Claude, Salesforce, and Slack be distinguished by execution surface and governance context?

## Canonical Deep Drift requirement

> Every material AI-assisted workflow that generates an interface or performs governed action should preserve a machine-readable execution manifest linking the visible AI surface to the exact reasoning-model identity; plugin and Skill identities and immutable versions or digests; connected enterprise sources and snapshot times; generated-interface identity and component state where available; MCP, API, CLI, or other action routes; authentication and administrator-managed permission state; governing business rules; action proposal, approval, validation, rejection, and commit events; transaction identifiers; human review or correction; and downstream artifact lineage. A generated dashboard, chat transcript, screenshot, exported document, or model response must not be treated as sufficient evidence that an underlying enterprise action was authorized or executed.

## Why this matters for Deep Drift Research

The creator-AI stack is moving from **assistant inside software** toward **AI as the interface to software**. That sounds elegant until provenance enters the room and ruins everyone's minimalist diagram.

The emerging architecture is:

```text
HUMAN INTENT
   -> MODEL REASONING
   -> DOMAIN SKILLS
   -> GENERATIVE UI
   -> ENTERPRISE GOVERNANCE
   -> ACTION / TRANSACTION
   -> ARTIFACT / STATE CHANGE
```

For Deep Drift, the research object is therefore not the chat, not the dashboard, and not the final PDF. It is the **cross-system execution graph** that explains how probabilistic reasoning became a deterministic business mutation.
