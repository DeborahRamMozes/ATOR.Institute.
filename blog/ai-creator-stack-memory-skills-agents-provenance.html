When AI Stops Being a Chat

Memory, skills, agents, mini-apps, documents, and the creator stack that now sits between human intention and finished work.

The most consequential change in generative AI is no longer visible in benchmark tables. It is happening around the model. Memory can be bounded by project. Files can persist independently of a conversation. Skills can be packaged as reusable procedures. Agents can act inside documents. Spreadsheets can become read-write mini-apps. Research workspaces can be copied with some layers preserved and other layers left behind. Automated flows can acquire identities of their own.

The language model is still there, obviously. But treating the model as the whole system now produces the same analytical quality as describing a hospital by naming the brand of its elevator.

From Conversation to Persistent Working State

Recent platform changes make one distinction unavoidable: conversation history, saved memory, project context, files, retrieval, and connected sources are not the same thing. They may all feel to the user like “the system remembers,” but their architectures, boundaries, persistence rules, and failure modes differ.

OpenAI's recent Project changes are especially useful for research because memory boundaries can now be altered within the lifecycle of a project. A project can be placed under a stricter project-only memory boundary rather than drawing from broader remembered context. That gives Deep Drift a clean experimental design: keep the human, files, model, and question constant while changing only the memory boundary.

The research question is no longer merely whether the model remembers. It is whether the same work remains stable when the mechanism of remembering changes.

The Input Route Has Become Part of the Computation

Copy-paste once looked like the least interesting part of an AI workflow. That was convenient, and wrong. Platforms now distinguish between direct pasted text, rich formatted paste, large-paste attachments, uploaded documents, library files, project sources, and connected cloud files.

For Deep Drift, identical content entering through different surfaces should be treated as a controlled experiment. A heading pasted as rich text may preserve hierarchy differently from the same heading inside an attachment. A long paste that becomes a file may be retrieved differently from message text. A Drive file may be treated differently from an uploaded copy of the same document.

This creates a new class of failure: ingestion-channel drift. The user believes the content is the constant. The system may be treating the route as part of the instruction.

Skills Are Becoming Procedural Infrastructure

Prompt engineering is quietly losing its privileged status. Major platforms increasingly package reusable behavior as skills, plugins, agent instructions, connectors, and callable procedures. This matters because procedural identity can now survive separately from a particular model.

The relevant Deep Drift experiment is therefore not “Which model is smartest?” It is: Does the same skill preserve its procedural identity when the reasoning engine, permissions, or execution environment changes?

A useful representation is:

memory + project + skill + model + permissions + tools + runtime = observed system behavior

Once this is accepted, a model name becomes an insufficient description of the system under test.

Mini-Apps Turn Artifacts into Mutable Interfaces

Google Sheets Canvas makes the change especially visible. A spreadsheet can now become a generated interactive interface that writes back to the source sheet. The artifact is no longer simply an output. It is an operational surface over persistent state.

source data ↔ generated interface ↔ human action

This creates a provenance problem that conventional document history does not fully solve. If a status value changes from OPEN to COMPLETE, did the human edit the cell directly? Did the human drag a card on the generated interface? Did an agent write the value? Did a formula change? Did imported data overwrite it?

The final state can be identical while the causal history is radically different.

Deep Drift therefore treats mutation-path provenance as a primary research object. Correct state is not enough. We need recoverable state history.

Document Generation Is Baseline. Round-Trip Fidelity Is the Real Test.

DOCX, PDF, XLSX, PPTX, and related file generation are rapidly becoming ordinary platform capabilities. The frontier is no longer whether a model can produce a downloadable file. The harder question is whether the artifact survives real work.

A proper benchmark is:

generate → download → human edit → re-import → AI revise → export → reopen elsewhere

Deep Drift measures semantic correctness, formatting fidelity, structural fidelity, editability, dependency survival, and provenance across that entire cycle.

Spreadsheet migration makes the problem obvious. A file can look correct while formulas, pivot relationships, named ranges, dependencies, or data types have silently changed. Visual similarity is not structural survival. Structural survival is not computational survival.

Agent Identity Changes the Meaning of Authorship

One of the most significant recent shifts is the emergence of explicit identities for automated flows. Google Workspace Studio, for example, is moving toward auditable flow identities, permissions, and machine-attributed actions. Microsoft is similarly moving from passive assistance toward app-native agents that create and alter documents, spreadsheets, and presentations.

This means “the user did it” is becoming an inadequate provenance statement.

The stronger chain is:

human owner → agent/flow identity → permissions → model/skill → source → action → artifact mutation → audit record

Deep Drift calls this agent identity continuity. The research question is whether that chain remains reconstructable after copying, exporting, migration, human editing, platform updates, or agent replacement.

Portable Workspaces Are Not Portable Histories

Recent workspace-copy features make another distinction visible. A research environment may preserve source files, generated artifacts, prompts, and configuration while leaving behind personal chat history, private notes, or later synchronization.

The copied workspace can therefore look complete while some of the human reasoning path that shaped it has vanished.

This is why Deep Drift separates:

  • source portability,
  • artifact portability,
  • configuration portability,
  • interaction-history portability,
  • human-note portability,
  • and synchronization continuity.

Artifact portability is not cognitive-history portability.

Deep Drift: Continuity Under Transformation

The platform changes now justify consolidating the research agenda around one larger construct: Continuity Under Transformation.

HUMAN ORIGIN
↓
MEMORY / PROJECT BOUNDARY
↓
FILES / RETRIEVAL / CONNECTED SOURCES
↓
SKILL / PROCEDURE
↓
MODEL
↓
AGENT / FLOW IDENTITY
↓
TOOLS / PERMISSIONS
↓
DOCX / PDF / XLSX / PPTX / SITE / MINI-APP
↕
EXTERNAL EDIT
↕
STATE MUTATION
↕
MIGRATION

The core benchmark families are now:

  • Context Continuity: memory boundaries, retrieval paths, ingestion surfaces.
  • Procedural Continuity: skill behavior across models and environments.
  • Artifact Continuity: document generation, round-trip fidelity, structural migration.
  • State Continuity: source data and generated-interface synchronization.
  • Research-State Portability: what survives when a workspace is copied.
  • Agent Identity Continuity: who or what performed each consequential action.
  • Workflow Continuity: survival across apps, platforms, feature changes, and agent replacement.

The Failure That Looks Successful

Hallucination remains important, but it is no longer the only interesting failure. A hallucination often looks wrong. A continuity failure can look completely correct.

The file opens. The formulas calculate. The presentation is polished. The mini-app responds. Nothing crashes.

What has disappeared is harder to see: the original source relationship, the human exclusion, the decision that was made three transformations earlier, the skill that altered the procedure, the agent that performed the mutation, or the permission boundary under which the action occurred.

That is the research frontier Deep Drift now needs to pursue with some aggression. Not because technology is failing to produce things, but because it is becoming extremely good at producing things while making the history of their production harder to recover.

The creator stack is becoming more capable. It must also become more accountable.
