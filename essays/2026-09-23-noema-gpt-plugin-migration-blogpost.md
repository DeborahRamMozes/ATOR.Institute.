# When the Container Changes: NOEMA, GPT Migration, and the Problem of Procedural Knowledge

**ATOR Institute Research Blog**  
**23 September 2026**  
**Author:** Deborah Ram Mozes

A product migration can look trivial from the outside. Change the container, move the workflow, continue working. For anyone who has built a serious compiler inside a conversational environment, the container is not trivial. The compiler may carry protocols, routing logic, tool relationships, project state, provenance rules, artifact behavior, and years of accumulated decisions.

That is why the current NOEMA itch is not really about whether a plugin is better or worse than a GPT. It is about what happens when a procedural system changes execution surfaces.

The earlier research record had already described the problem in architectural terms: conversation, compiler, skills or plugins, tools and connectors, state, artifacts, and provenance need to operate as a coherent working system. When those layers fragment, the human becomes the memory archive, the workflow becomes harder to reproduce, and the intellectual structure becomes harder to audit.

The 23 September migration notice changes the immediate research question, but it does not prove a causal relationship between the earlier reports and the product change. That distinction matters. Research becomes fiction very quickly when chronology is promoted to causation merely because the story feels satisfying.

The procedural-knowledge problem is more concrete. A mature compiler may contain protocol hierarchy, routing decisions, failure handling, testing logic, artifact lineage, and project-specific architecture. Moving that system into a reusable modular surface can change its portability, reproducibility, inspectability, and operational accessibility.

That creates four separate evidence questions: does the platform process the compiler, can authorized personnel inspect it, can other users obtain it, and can its functionality be reproduced elsewhere? Those claims should never be treated as synonyms.

The correct response is experimental rather than theatrical. Preserve a canonical pre-migration copy. Freeze the current instructions, reference files, tools, connectors, permissions, and provenance. Run a pre-migration behavioral suite. Complete the migration. Run the same suite again. Then classify every element as preserved, changed, lost, or unknown.

The interesting thing about this research is that both capability and governance can rise at the same time. A more modular architecture can make sophisticated workflows easier to execute while also making the platform boundary more consequential. The object of study is therefore the control boundary around procedural knowledge, not an assumed motive.

The NOEMA question survives as an itch: **when advanced user-built compilers are migrated into platform-managed plugin architectures, what happens to the portability and reproducibility of the author's procedural knowledge, and what controls govern inspection, extraction, duplication, and redistribution?**

That question is still open.
